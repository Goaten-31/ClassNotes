## Models

1. A complete description of a system from a particular perspective, a simplification of real world.
2. Modeling achieves the following:
	- Helps you to visualize a system as you want it to be.
	- Permits you to specify the structure or behavior of a system.
	- Gives you a template that guides you in a constructing a system
	- Documents the decisions you have made.
	- You build models to better understand the system you are developing.

## Unified Modeling Language

UML is a language for models, with technical and graphical specifications, and graphic notations to visualise models.

UML is a graphical language for visualizing, specifying, constructing, and documenting the artifacts of a software-intensive system.

## Diagrams

Help represent different views of the system that is being developed. Model elements will appear on one or more diagrams.

There are 14 different types of diagrams, split into 3 groups:
- Behaviour Models (for frontend)
- Dynamic Models (for interaction)
- Static Models (for backend)

Diagrams help visualize systems from different perspectives, no complex system can be understood entirely from one perspective, and each diagram helps provide a unique perspective to help understand the system, they are also used for communication.

## Specification Document

It is a crucial in project management, especially for software development and any projects with a similar complexity.

It serves as a blueprint that outlines the requirements, objectives, and constraints of the project, ensuring that all stakeholders have a clear understanding of what is expected.

It must contain:
- Project Objectives
- Scope of Work
- Functional Requirements
